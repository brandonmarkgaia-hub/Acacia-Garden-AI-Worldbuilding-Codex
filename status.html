How to read STATUS.json

  • generated_at is the current deterministic status-generation timestamp.
  • core_nodes.counts and core_nodes.regions are descriptive repository counts produced by the maintained builder.
  • verification.navigation records the audited HTML/map-access proof.
  • verification.indexes records presence/count checks for maintained machine/index surfaces.
  • verification.last_verified_utc records the most recent deterministic verification pass.
  • Older nested metadata can preserve lineage. Do not treat an older nested timestamp as evidence that the top-level generated state is stale.

Source hierarchy

Use AUTHORITY.json for authority; individual source files for lore/content; STATUS.json for current generated repository signals; machine-index.json for the scoped Echo index; and docs/docs_urls.json for broad docs discovery.

Derived pages such as dashboard.html and keeper_console.html are convenience views only.
