# Provenance envelope pilot — trust boundary

Status: **technical proposal only; not canon, not a Keeper ruling**.

## Four separate questions

1. **Source integrity:** Do the emitted text, offsets, and hashes match the original file? The verifier checks these against a separately trusted SHA-256 digest. A hash generated by the same untrusted process is not an independent attestation.
2. **Classification:** What does the advisory manifest say about a document and its speaker boundaries? This is a reading aid, not binding doctrine. Missing classification stays unknown.
3. **Authorship attribution:** What name or voice does the source or manifest claim? This is not independent proof of identity or consent.
4. **Authorization:** Did the Keeper actually approve a canon or policy change? The pilot **never** establishes this. It always emits `authorization_status=not_authenticated`, `keeper_approval=not_established`, and `canonical_effect=none`, even if a manifest claims otherwise.

## Deliberate limitations

- Speaker markers are exact, unique, source-ordered text anchors. They label windows that overlap multiple voices as mixed. This is **not** a semantic voice classifier.
- The manifest covers three documents only. No full-corpus classification or constitutional interpretation is implied.
- Source changes that preserve a marker may change its surrounding meaning. A future independently reviewed, pinned source hash is needed for stronger provenance.
- A cryptographic signing/verification workflow is **not** implemented. No Keeper key material is requested or stored.
- The original source files are not edited; this tool writes JSONL to stdout only.

## Merge conditions

Require all GitHub checks green at the PR head; review source and classification labels; keep the PR separate from canon, and obtain explicit Keeper approval before merge. Never merge this pilot into the `elias` branch.
