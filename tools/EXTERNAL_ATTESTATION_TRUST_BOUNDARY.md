# External attestation trust boundary

Status: non-canonical technical protocol. No Keeper attestation has been issued.

The tool verify_external_attestation.py verifies an Ed25519 signature against a public key provided independently by a human operator. It binds a repository identifier, an exact 40-character commit SHA and one of two narrowly defined scopes.

## Key security requirements
- Keeper generates and controls the private key outside this repository. Never commit it or share it with the assistant.
- Obtain the public key and its fingerprint from a genuinely independent trusted channel. A key committed to this repository does not authenticate its own ownership.
- Sign the exact canonical UTF-8 JSON statement generated by canonical_statement; include the newline.
- Publish the signed statement and detached signature only after independent review.
- Record revocation, rotation and supersession procedures. A valid signature remains cryptographically valid even after revocation; consumers must check revocation state separately.
- Verification of the supplied public key proves only that the matching private key signed the bytes. It does NOT establish that the key belongs to the Keeper, that a release was authorized, or that any document is canon.
- The scope integrity_acknowledgment is not a canon approval. The scope keeper_reviewed_release is a claimed release review, subject to separately authenticated key ownership and governance authorization.
- Neither scope authorizes editing or merging original Garden text.

## Current status
No trusted Keeper key, external fingerprint, signature or attestation is provided by this repository. Any test keys are ephemeral fixtures and must never be presented as Keeper credentials.

## Next Keeper action
When ready, choose an independent key custody and public-key verification process. Do not create or claim a Keeper signature on the Keeper's behalf.
